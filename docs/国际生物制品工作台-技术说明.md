# 兽用生物制品监管追踪工作台 (Veterinary Biologics Tracker)

面向**猫犬兽用生物制品**（疫苗 / 诊断试剂 / 治疗性生物制品）的自动化追踪工作台，
覆盖 **美国 USDA/CVB** 与 **欧盟 EMA/CVMP** 监管获批信息。

---

## 功能对照

| # | 需求 | 实现 |
|---|------|------|
| 1 | 定期抓取官方数据库，记录产品名称/获批编号/企业/适应症/剂型/规格/获批日期 | `ingest.py` 抓取层 + `db.py` 结构化存储；内置示例数据，抓取函数可接入真实监管源 |
| 2 | 按国家/地区、物种、产品类型分类 | 数据库维度字段 + 前端筛选（地区/物种/类型/状态）+ 统计图表 |
| 3 | 自动对比历史，识别新增/状态变更/撤回并标注变更日期 | `db.ingest_dataset()` 差异引擎：NEW / UPDATED / STATUS_CHANGE / WITHDRAWN，全部写入 `change_log` 并标注日期 |
| 4 | 搜索与筛选（产品名/企业/适应症） | 顶部搜索框（模糊匹配）+ 多维下拉筛选 |
| 5 | 表格 + 图表统计（年度趋势、企业分布等） | 数据表格 + Chart.js：年度获批趋势、Top10 企业分布、产品类型/状态分布 |
| 6 | 导出 Excel / PDF | `/api/export/excel`、`/api/export/pdf`，含产品表 + 变更记录 + 统计，支持中英双语 |
| — | 简洁界面 + 中英切换 + 更新通知 | 单页应用，右上角语言切换；钟形通知面板 + 角标 + 每 30s 轮询；点击「更新数据」触发抓取并弹通知 |

## 接入真实监管数据源（已实装）

真实的解析逻辑位于 **`regulatory.py`**，并通过 `ingest.py` 的 `pull_update(live=True)`
无缝接入现有流程。默认仍为示例数据模式（见下方开关），开启后逐源抓取、逐源容错。

### 已实现的真实解析器
- **USDA / CVB（已实装并验证）**
  - 数据源：APHIS 官方「Current Veterinary Biologics Product Catalog」PDF 代码本
    `https://direct.aphis.usda.gov/sites/default/files/currentprodcodebook.pdf`
  - 解析：用 `pdfplumber` 逐页抽取「产品清单」区段（Vaccines / Diagnostics / …），
    提取每行 `PCN`（产品编号）→ `approval_number`、生产商许可号 `VLN` → 通过
    「Numerical Listing of Licenses」映射为企业名称（`manufacturer`）、剂型/工艺
    （`dosage_form`，如 Killed Virus / Modified Live Virus）、物种（`species`，按猫犬关键词推断，
    非猫犬产品自动过滤）。经真实目录验证：共解析出 **62 条猫犬产品**（44 犬 / 18 猫），
    正确过滤掉 363 条畜禽/水产产品，企业名称全部解析成功。
  - 本地缓存：`data/usda_catalog.pdf`，默认 1 天内复用（`USDA_CATALOG_CACHE_DAYS`），
    仅首次拉取较慢，后续解析为秒级。
- **EMA / CVMP（已实装实时抓取，无需 API Key / 无需登录）**
  - 数据源为欧盟 UPD（Union Product Database）公开检索页
    `https://medicines.health.europa.eu/veterinary/en/search-medicines`。
    该页面是 **Drupal 服务端渲染**（`search_api` 视图），`requests` 直连即可拿到
    完整产品行，**不需要** UPD 只读 API、不需要账号。
  - 历史误判说明：早期版本请求的是站点根 `…/veterinary`，它会 301 跳到
    **语言选择壳页**（`select-language`），页面里自然没有产品数据；同时
    `_parse_ema_html()` 曾是 `return []` 的占位实现，`EMA_API_URL` 分支里也只有
    `raw_recs = []` 加一句 TODO。两者叠加造成「JS 渲染、必须配 `EMA_API_URL`」的
    错误结论——实际上即便填了 `EMA_API_URL` 也不会有任何数据。
  - 每行可解析字段：产品名、UPD 永久 ID、靶动物（Target species）、活性成分、
    剂型、授权状态（Authorised / Suspended / Withdrawn）。
    `approval_number` 采用 `UPD-<永久ID>`（同一商品名在多个成员国分别授权，
    各自拥有独立 UPD ID，按 ID 去重）。
  - 分页固定 10 条/页（`items_per_page` 被视图忽略），全量约 5,074 条 ≈ 508 页；
    站点限流严格（易触发 HTTP 429 / 连接重置），因此默认按
    **最近更新时间倒序**（`EMA_SORT_BY=prod_search_changed`）只抓前 `EMA_MAX_PAGES`
    页做增量，单页失败会自动重试（指数退避）且不影响整批。
  - 一次性全量回填：`EMA_MAX_PAGES=600`（耗时较长，建议单独手动执行）。

### 字段映射（统一规范）
所有抓取结果都归一化为下游 `db.ingest_dataset()` 消费的同一套字段，保证差异引擎 /
通知 / 导出 / 前端完全复用：
`region, species, product_type, product_name, approval_number, manufacturer,
indication, dosage_form, strength, approval_date, status, source`

### 错误处理与日志
- 每个抓取器均 `try/except` 全覆盖：**网络超时、HTTP 非 200、非预期格式、解析异常**
  全部捕获并写入 `data/ingest.log`（按大小滚动），且**绝不向上抛出**——失败即返回
  `([], meta)`，由 `ingest.py` 按源回退到示例切片，流程不中断。
- 每条记录经 `normalize_record()` 校验（必填字段、枚举归一），非法记录单独计数并跳过，
  不污染整批。
- 实时源使用独立于示例的 `source` 标签（`USDA-CVB` / `EMA-CVMP`），配合
  `db.ingest_dataset()` 的**来源感知撤回**：仅当某产品所属 `source` 出现在本次抓取源中、
  且本次缺失时才标记为撤回。因此切换到实时数据**绝不会误撤回示例演示数据**。

### 运行开关（环境变量）
| 变量 | 默认值 | 说明 |
|------|--------|------|
| `USE_LIVE_SOURCES` | `0` | 设为 `1` 时，定时任务与默认「更新数据」改用真实监管源 |
| `REPLACE_ON_LIVE` | `0` | 设为 `1` 时，实时拉取前清空示例数据，仅保留实时/真实数据 |
| `USDA_CVB_CATALOG_URL` | 官方 PDF | 可指向镜像/本地文件 |
| `EMA_API_URL` | 空 | **一般不需要**。仅当你有自建/第三方 JSON 端点时使用；填了也需自行实现 JSON→字段映射 |
| `EMA_SEARCH_URL` | UPD 公开检索页 | 实时 EMA 抓取的真实入口（服务端渲染，免鉴权） |
| `EMA_MAX_PAGES` | `40` | 每次抓取的最大页数（10 条/页）。全量回填设为 `600` |
| `EMA_SORT_BY` | `prod_search_changed` | 排序键；默认「最近更新」倒序，便于增量捕获变更。置空则用相关度默认序 |
| `EMA_SORT_ORDER` | `DESC` | 排序方向 |
| `EMA_FETCH_WORKERS` | `3` | 并发抓取页数；调高易触发 HTTP 429 |
| `EMA_MAX_RETRIES` | `4` | 单页失败重试次数（指数退避） |
| `EMA_RETRY_BASE_DELAY` | `2.0` | 重试初始等待秒数 |
| `USDA_CATALOG_CACHE_DAYS` | `1` | USDA PDF 本地缓存有效期（天） |
| `REGULATORY_TIMEOUT` | `30` | 抓取超时（秒） |
| `INGEST_INTERVAL` | `3600` | 定时抓取周期（秒） |
| `VET_DB_PATH` | `data/vet_biologics.db` | 数据库路径（便于测试/多实例） |

### 手动触发（前端）
勾选右上角 **「实时数据源」** 复选框后点「更新数据」，即向 `/api/ingest` 发送
`{"live": true}`；再勾选 **「替换示例」** 可发送 `{"live": true, "replace": true}`。
前端会显示本次抓取结果（新增/更新/状态变更/撤回）及回退来源提示。

建议的真实入口（请遵守各站点 ToS / API 协议）：
- 美国 USDA APHIS | Center for Veterinary Biologics：官方产品目录 PDF / VetBio 搜索
- 欧盟 EMA | Union Product Database (UPD) 只读 API / 公开兽医药品网站

在线抓取受网络/反爬限制时，也可改为下载官方发布的文件后由本工具解析入库。

## 自动更新与通知

- 后端启动后运行一个后台线程，按 `INGEST_INTERVAL`（默认 3600 秒，可用环境变量覆盖）周期调用抓取。
- 每次抓取与历史库做差异比对，**仅当产生真实变更**（新增/更新/状态变更/撤回）时才生成通知。
- 前端每 30 秒轮询 `/api/notifications`，出现新通知时弹出提示并更新角标；点击铃铛可查看并「全部已读」。
- 首次基线导入不计入未读通知（避免噪音），仅作历史留存于「变更记录」面板。

> 注：当前通知为**应用内通知**。如需邮件/企业微信/Slack 推送，可在 `db.ingest_dataset()`
> 产生变更后接入对应连接器（本环境连接器默认未连接，需先配置）。

## 已知限制与后续

- 示例数据用于演示结构与时序趋势，并非实时监管数据；上线前务必接入真实源（见上）。
- 图表依赖 Chart.js CDN；浏览器离线时图表区会提示，表格与导出不受影响。
- 可扩展方向：多语言术语库、监管原文链接、撤回原因字段、邮件/IM 推送、增量导入调度看板。
