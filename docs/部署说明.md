# 部署与维护手册

> 本手册面向日常维护者，说明两个工作台如何构建、更新、发布与排障。
> 仓库根目录即工作目录，**不要移动或重命名文件**，否则本地定时任务会失效。

---

## 1. 稳定链接（GitHub Pages）

仓库：<https://github.com/qqkiky/vet-drug-workbenches>

| 入口 | 链接 |
|---|---|
| 总入口页 | <https://qqkiky.github.io/vet-drug-workbenches/> |
| 国际兽用生物制品监管追踪 | <https://qqkiky.github.io/vet-drug-workbenches/intl/> |
| 国内 / 进口兽药注册与审批 | <https://qqkiky.github.io/vet-drug-workbenches/cn/> |

发布机制：每次向 `main` 分支推送代码或数据，GitHub Actions 的
`pages.yml` 会自动执行 `publish_site.py` 组装站点并发布，无需手动操作。

## 2. 目录结构速览

```
根目录（= 仓库）
├── dist/            国际工作台构建产物（由 build_static.py 生成）
├── static/          国际工作台前端源码
├── data/            国际工作台数据库（vet_biologics.db）与抓取缓存
├── workbench/       国内/进口工作台（drugs.db、build_web.py、web/ 等）
├── publish_site.py  组装 GitHub Pages 站点（intl/ + cn/ + 入口页）
├── git_sync.py      本地更新后自动提交并推送
└── docs/            文档与变更日志
```

## 3. 云端自动更新

`.github/workflows/daily-intl.yml` 统一维护两个工作台，并在北京时间
**每周三、每周五 22:00** 自动运行（GitHub cron 使用 UTC，对应
`0 14 * * 3,5`）。电脑关机不影响执行。

流水线依次完成：

1. 国际：实时抓取 USDA/CVB 与 EMA/CVMP，增量写入并重建 `dist/`；
2. 国内：实时抓取农业农村部公告和国家兽药基础数据库临床审批，增量写入
   `workbench/drugs.db`；
3. 重建国内网页、PWA 资源和 Excel 工作簿；
4. 更新国内、国际同步状态及 `docs/变更日志.md`；
5. 自动提交至 `main`；`pages.yml` 随后重新发布网站。

容错规则：

- 单个来源失败：保留已有数据，其他来源继续更新，日志标记 `partial`；
- 同一工作台的全部官方来源失败：该工作台不发布半成品；
- 国内、国际均失败：工作流失败且不提交旧数据；
- 空响应不会被当成成功，下一次计划运行会自动重试。

手动触发：GitHub 仓库 → **Actions** → 「国内与国际工作台每周同步」→
**Run workflow**。

首次部署或修改同步脚本时，工作流也会自动实跑一次，用于验证云端网络和构建链路。

## 4. 手动构建与发布

### 4.1 国际工作台

```bash
# 抓取 + 入库 + 重建 dist/
.venv\Scripts\python daily_sync.py

# 本地预览组装后的站点
.venv\Scripts\python publish_site.py --out _site
```

确认无误后提交推送即可发布：

```bash
git add -A
git commit -m "update: 手动更新"
git push
```

### 4.2 国内/进口工作台

```bash
# 抓取农业农村部公告并生成工作簿（xlsx）
.venv\Scripts\python workbench\build_workbench.py

# 导入临床审批 + 补全适应症（视需要）
.venv\Scripts\python workbench\ingest_vdts_clinical.py
.venv\Scripts\python workbench\fill_all_indications.py

# 从数据库重建 web/ 静态站点
.venv\Scripts\python workbench\build_web.py

# 提交推送
.venv\Scripts\python git_sync.py
```

## 5. 本地开发环境

```bash
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

国内下载慢时可加阿里云镜像：

```bash
.venv\Scripts\pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
```

GitHub 推送依赖 GitHub CLI 登录：

```bash
gh auth status        # 查看登录状态
gh auth login         # 未登录时执行，浏览器授权
gh auth setup-git     # 让 git push 使用 gh 的登录凭据
```

## 6. 故障排查

| 现象 | 原因与处理 |
|---|---|
| 国际或国内工作台数据源显示 ✗ | EMA 站点限流（HTTP 429）或 USDA 超时，属正常波动；云端会逐源容错，次日自动重试。连续多日失败可到 Actions 页面查看日志。 |
| 云端周三/周五 22:00 任务没准点跑 | GitHub 调度高峰可能延迟几分钟到几十分钟，属正常；也可在 Actions 页面手动 Run workflow。 |
| 数据已更新但网页没变 | 检查是否执行了 `git_sync.py` 并推送成功；推送后等 1–3 分钟让 GitHub Pages 重新发布。 |
| 推送失败：authentication required | 在命令行执行 `gh auth login` 重新登录，再 `gh auth setup-git`。 |
| 网页打开 404 | 确认链接路径以 `/intl/` 或 `/cn/` 结尾；总入口为仓库根路径。 |
| PWA 图标/离线缓存异常 | 清理浏览器缓存后重新「添加到主屏幕」。 |

## 7. 隐私与安全

以下内容由 `.gitignore` 排除，不会进入公开仓库：

- `.venv/`、`__pycache__/` 等运行环境；
- `.workbuddy/`、`workbuddy-session/`、`daily-report/` 本地会话与日报；
- `workbench/pages/` 抓取缓存、各类 `*.bak*` 备份；
- `workbench/email_recipients.json`（含收件人邮箱）；
- Tailscale 安装包、隧道脚本等本机工具。

## 8. 常见问题

**两个工作台为什么放在同一个仓库？**

一个仓库对应一个 GitHub Pages 站点，因此两个工作台共用仓库，
在站点内以 `/intl/` 和 `/cn/` 两个子路径呈现，入口页可互相跳转。

**之前的 CloudStudio 链接还要用吗？**

不需要。GitHub Pages 链接长期稳定、无需沙箱续期；原 CloudStudio
链接可保留作历史参考，也可在 WorkBuddy 自动化中停用部署步骤。
